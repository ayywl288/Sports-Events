# 校园体育赛事管理系统 — 问题清单与解决方案

> 范围：赛事、报名审核、赛程、成绩、公告（含其依赖的账号权限与初始化数据）
> 方式：静态代码走查 + 实体/表结构比对 + 前后端契约比对 + `mvn compile` 验证
> 状态：**分析稿**。修复落地情况见 [`修复记录-v1.1.0.md`](./修复记录-v1.1.0.md)（P0 8/8、P1 25/25、P2 20/23 已闭环）
> 日期：2026-11-02

## 0. 结论摘要

- `mvn compile` 通过（EXIT=0），**不存在编译期错误**；所有问题都在运行期与前后端契约层。
- 走查共发现 **56 项问题**，其中 **P0 阻断级 8 项**，P1 严重 25 项，P2 一般 20 项，P3 优化 3 项。
- 当前系统**无法完成一条完整的业务主线**：赛事发布按钮不出现 → 学生无赛事入口 → 报名后审核按钮不出现 → 成绩录入必报 SQL 错误 → 公告类型筛选无效。
- 根因集中在 4 处：
  1. **状态值域三套并存**（后端 Integer / 前端字符串 / 文档英文枚举）；
  2. **实体与表结构不一致**（`sport_item.current_participants`、`result` 的 4 个字段）；
  3. **VO 字段命名与前端表格列不一致**（大量空白列、错误分支永远不成立）；
  4. **Controller 绕过 Service 直接 `save/updateById`**（校验全部缺失）。
- 建议按第 6 节顺序修：先做「状态值域 + 表结构 + VO」三件事，可一次性消除 8 个 P0 中的 6 个。

### 1.1 技术栈与分层

| 层 | 实现 |
|----|------|
| 后端 | Spring Boot 3.2.1 + MyBatis-Plus 3.5.5 + Spring Security 6 + JWT（jjwt）+ Druid + Knife4j |

| 分层 | Controller → Service(Impl) → Mapper；`common/result` 统一响应，`common/exception` 全局异常 |

### 1.2 模块与数据流

```
event(赛事) 1─n sport_item(项目) 1─n registration(报名) 1─1 result(成绩)
   │                                  │                      │
   └──────────── 1─n schedule(赛程) ───┴──────────────────────┘
                        news(公告) ──可选关联──> event
```

关键状态（后端唯一权威定义）：

| 对象 | 值域 | 说明 |
|------|------|------|
| `event.status` | 1/2/3/4 | 草稿/报名中/进行中/已结束 |
| `registration.status` | 1/2/3/4 | 待审核/已通过/已拒绝/已取消 |
| `schedule.status` | 1/2/3 | 未开始/进行中/已结束 |
| `news.status` | 0/1/2 | 草稿/已发布/已下架 |

**这三套值域是本次多数 P0 问题的源头**：文档写英文枚举（DRAFT/PENDING），后端用 Integer，前端按英文枚举比较。

## 2. P0 阻断级问题（8 项，必须先修）

> P0 定义：导致主流程无法走通，或必然返回 500。

### EV-P0-01 赛事状态值域不一致，导致「发布」按钮永不出现

| 项 | 内容 |
|----|------|
| 位置 | `frontend/src/views/event/list.vue:19-24,57-59`；`backend/.../event/vo/EventVO.java:89` |
| 现象 | 列表状态下拉传 `DRAFT/PUBLISHED/ONGOING/ENDED`；后端 `EventQueryDTO.status` 是 `Integer`，一选状态就 400「参数类型错误」。表格里 `row.status === 'DRAFT'` 永远为 false，**发布/删除按钮永不渲染**，取消按钮对所有记录都显示。 |
| 根因 | 前端按设计文档的英文枚举实现，后端按数据库 TINYINT 实现，双方从未对齐。 |
| 方案 | ① 全系统统一「数值码 + statusName」：前端判断只用数字（1~4），展示只用后端返回的 `statusName`；② 状态标签颜色改由数字映射；③ 筛选项 `value` 改 1/2/3/4；④ 同步修正 `getStatusType()`。 |
| 验收 | 草稿赛事显示「发布」按钮，点击后列表状态变为「报名中」；按状态筛选返回正确子集且无 400。 |

### REG-P0-01 学生端无法完成报名闭环（无入口 + 按钮被屏蔽）

| 项 | 内容 |
|----|------|
| 位置 | `frontend/src/router/index.ts:29-34,55-60`；`views/event/detail.vue:137-141` |
| 现象 | 赛事列表路由 `roles: ['ADMIN','TEACHER']`，学生菜单里**没有任何赛事浏览入口**；即使从「我的报名」跳进详情页，`canRegister` 判断 `status === 'PUBLISHED'`（实际是 2）永远为 false，**报名按钮不渲染**。 |
| 根因 | 路由把「赛事管理」当成了唯一赛事入口；详情页状态判断用了错误的字符串枚举。 |
| 方案 | ① 新增学生侧「赛事浏览」路由（如 `/events/browse`，无 roles 限制，只展示 `status=2` 且报名窗口内的赛事）；② 详情页状态判断改数值 2，同时用 `regStartDate/regEndDate` 做时间窗判断；③ 管理端保留 `/events` 的 roles 限制。 |
| 验收 | 学生登录 → 看到赛事列表 → 进详情 → 点「立即报名」→ 生成待审核记录。 |

### REG-P0-02 报名审核入口失效（VO 类型错 + 前端比较错）

| 项 | 内容 |
|----|------|
| 位置 | `backend/.../registration/vo/RegistrationVO.java:26`；`RegistrationServiceImpl.java:255`；`frontend/.../registration/list.vue:42` |
| 现象 | `RegistrationVO.status` 声明为 `String`，而实体 `Registration.status` 是 `Integer`，`BeanUtils.copyProperties` 遇到类型不可赋值会**静默跳过**，所以接口返回的 `status` 恒为 `null`；前端再按 `row.status === 'PENDING'` 判断，「通过/拒绝」按钮**永不显示**。 |
| 根因 | VO 与实体类型不一致 + 前端英文枚举。 |
| 方案 | ① VO 的 `status` 改为 `Integer`（保留 `statusName` 供展示）；② 前端判断改 `row.status === 1`；③ 全项目检索其它「VO 用 String 承接 Integer 状态」的同类写法（`Schedule`/`News` 已存在同名隐患）。 |
| 验收 | 待审核记录展示「通过/拒绝」按钮，操作后状态与列表同步刷新。 |

### REG-P0-03 报名状态筛选恒为空

| 项 | 内容 |
|----|------|
| 位置 | `frontend/.../registration/list.vue:13-16`；`RegistrationController.java:79`；`RegistrationServiceImpl.java:182` |
| 现象 | 前端传 `status=PENDING`，后端用字符串直接与 TINYINT 列比较，MySQL 隐式转换后为 0，**查不到任何数据**；且 Controller 参数类型就是 `String`，绕过了类型校验。 |
| 根因 | 同上，状态值域不一致。 |
| 方案 | ① Controller/Service 的 `status` 参数统一为 `Integer`；② 非法值返回 400；③ 前端筛选项改数字。 |
| 验收 | 选择「待审核」返回全部待审核记录；`status=abc` 返回参数错误而非空列表。 |

### RES-P0-01 成绩实体与 `result` 表结构严重不匹配（必 500）

| 项 | 内容 |
|----|------|
| 位置 | `backend/.../result/entity/CompetitionResult.java:30-78`；`docs/04-DB/schema.sql:198-222` |
| 现象 | ① 实体**缺少 `registrationId`**，而表中 `registration_id BIGINT NOT NULL` 且无默认值 → INSERT 必报 `Field 'registration_id' doesn't have a default value`；② 实体多出 `scoreUnit / isRecord / recorderId` 三个字段，表中对应列为 `score_text / 无 / record_by` → MyBatis-Plus 生成的列清单包含 `score_unit, is_record, recorder_id`，**SELECT 也报 Unknown column**。结果：成绩列表、排名、我的成绩、录入全部不可用。 |
| 根因 | 成绩模块存在两套实体（`Result` 与 `CompetitionResult` 同映射 `result` 表），开发时混用了其中一套，`Result` 的映射是对的却没人用。 |
| 方案 | ① 二选一：删除 `CompetitionResult`，全面改用已正确映射的 `Result`；或保留 `CompetitionResult` 但补齐 `registrationId`、`scoreText`、`recordBy`、`recordTime` 的 `@TableField` 并删掉 `isRecord`；② 全模块统一后删除多余实体，避免再次混用；③ 增加一条「实体-表结构一致性」的启动自检或单测。 |
| 验收 | 录入一条成绩成功落库；成绩列表能按赛事/项目查询；`registration_id` 有值且与报名记录一致。 |

### RES-P0-02 成绩录入完全绕过业务校验

| 项 | 内容 |
|----|------|
| 位置 | `backend/.../result/controller/CompetitionResultController.java:58-60,74-77` |
| 现象 | `competitionResultService.save(result)` 直接把前端 JSON 落库。不校验：报名是否存在且 `status=2`、赛事是否进行中/已结束、项目是否属于该赛事、该报名是否已有成绩、赛程是否存在、是否是本人项目。可以给任意 `userId` 记任意成绩，名次/积分也完全由前端填。 |
| 根因 | Controller 直接调用 MyBatis-Plus 通用 `save/updateById`，Service 层只有查询方法。 |
| 方案 | ① 新增 `ResultService.saveResult(ResultDTO)`，在 Service 内完成：查报名→校验状态与归属→校验赛事状态→校验唯一→写库；② Controller 只做参数接收与鉴权；③ 删除 Controller 中的直接 `save/updateById`。 |
| 验收 | 给未通过报名的用户记成绩被拒（BIZ 错误码）；重复录入提示「成绩已存在」；跨赛事项目被拒。 |

### RES-P0-03 成绩导入/导出/模板三个按钮均为死链

| 项 | 内容 |
|----|------|
| 位置 | `frontend/.../result/list.vue:316-360` |
| 现象 | 导出 `window.open('/results/export?...')`、模板 `/results/template`、导入 `post('/results/import')`。三个地址都**少了 `/api` 前缀**、**不携带 Authorization**，后端也**根本没有这三个接口**。点击后 404 或落到前端路由；导入还因全局 `Content-Type: application/json` 无法上传文件。 |
| 根因 | 功能只做了 UI 占位，`pom.xml` 里的 EasyExcel 依赖从未被使用。 |
| 方案 | ① 后端补 `GET /api/results/export`、`GET /api/results/template`、`POST /api/results/import`（multipart）；② 导出/模板改用带 token 的 `axios` 请求 + `Blob` 下载（不能用 `window.open`）；③ 导入前端使用 `multipart/form-data` 且单独覆盖 Content-Type；④ 导入返回 `成功数/失败明细`。 |
| 验收 | 导出得到含表头的 xlsx；用导出模板回填后导入成功，错误行有明确提示。 |

### AUTH-P0-01 每次启动重置全部用户密码

| 项 | 内容 |
|----|------|
| 位置 | `backend/.../config/PasswordInitializer.java:23-49` |
| 现象 | `CommandLineRunner` 在**每次应用启动**执行 `UPDATE sys_user SET password = <123456 的 BCrypt>`。任何人改过的密码在重启后都会失效；生产环境等于把全站密码固定为 123456。 |
| 根因 | 用「启动时重置」来掩盖初始化脚本密码哈希不正确的问题（见 AUTH-P1-01）。 |
| 方案 | ① 直接删除该 `CommandLineRunner`；② 用一份正确的 BCrypt 哈希修复 `schema.sql`/`data.sql`；③ 若确实需要演示账号，改为 `dev` profile 下的一次性数据脚本，或仅在「用户表为空」时初始化；④ 密码策略改为首次登录强制修改。 |
| 验收 | 修改密码后重启服务，旧密码仍失效、新密码可登录；全新库初始化后文档中的密码可直接登录。 |

- [ ] 学生看不到他人报名；管理员可取消任意状态

**赛程**
- [ ] 同场地同时段保存被拒；时间倒挂被拒；日期超出赛事区间被拒
- [ ] 有成绩的赛程不可删除
- [ ] 已结束赛程不可编辑

**成绩**
- [ ] 未通过报名不能录成绩；重复录入被拒
- [ ] 时间类升序、距离/分数类降序排名正确；并列名次正确
- [ ] 导出 → 修改 → 导入 闭环成功，错误行有明细
- [ ] 学生只能看到自己的成绩

**公告**
- [ ] 学生看不到草稿/已下架
- [ ] 类型筛选与字典一致，新建类型合法
- [ ] 详情显示作者/类型名；浏览量递增且并发不丢
- [ ] 富文本中的 `<script>` 被过滤

**账号**
- [ ] 改密后重启服务，旧密码失效
- [ ] 禁用用户的旧 token 立即失效
- [ ] 刷新页面后菜单与权限保持

## 8. 附：需要人工确认的 3 个业务决策

1. **「赛事取消」的终态**：改为独立状态 5，还是回退草稿？影响历史报名的处置与统计口径。
2. **名额统计口径**：待审核是否占名额？建议「不占，通过时校验」，但会带来「通过时才发现满员」的体验问题，需产品确认是否引入候补。
3. **报名唯一约束**：取消/被拒后是否允许重新报名？若允许，现有唯一索引必须调整（涉及数据迁移）。
